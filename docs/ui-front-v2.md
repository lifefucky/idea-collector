## Спецификация фронта Mini App «Карман» v2 (визуальный референс)

Этот документ описывает, как адаптировать новый визуальный референс фронта под Telegram Mini App, **минимально меняя стиль** и не ломая текущую архитектуру (`webapp/index.html`, `webapp/src/main.tsx`, `PocketApp`, `IdeaList`, `SourcesPane`).

---

## 1. Навигация и экраны

- **Одна Mini App** по адресу `/`:
  - `view: "ideas"` — список идей + поле захвата (главный экран).
  - `view: "idea-card"` — карточка отдельной идеи.
  - `view: "sources"` — список источников.
  - `view: "source-overlay"` — модальное добавление источника.

- **Нижний локальный бар** (React‑компонент, не Telegram Tabbar):
  - 3 иконки слева направо:
    - **Идеи** — активирует `view: "ideas"`.
    - **Sources** — активирует `view: "sources"`.
    - **Лента** — **затемнённая, неактивная заглушка**:
      - `aria-disabled="true"`, `pointer-events: none`;
      - визуально тусклее, без цветной «таблетки» выбранного состояния.
  - `view` хранится в состоянии `PocketApp`; `div.pocket-ideas` и `div.pocket-sources` всегда смонтированы, переключение через `hidden`, как сегодня.

---

## 2. Safe area и интеграция с Telegram

- В `webapp/index.html` уже есть:
  - `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover" />`;
  - паддинги с учётом `env(safe-area-inset-bottom, 0px)`.

- **Требование** v2:
  - не удалять этот паттерн; любые новые sticky‑элементы (нижний бар, статус‑строки) считают нижний отступ так:
    - `padding-bottom = высота бара + env(safe-area-inset-bottom, 0px)`;
  - верхний отступ контейнера должен учитывать верхнюю safe area (`safe-area-inset-top`) либо через CSS, либо через SDK (`viewport.contentSafeAreaInsetTop()`).

- Использование `@telegram-apps/sdk` остаётся как в v1:
  - `init()`, `restoreInitData()`, `retrieveLaunchParams()` для `initData`;
  - `themeParams.mountSync()` / `themeParams.bindCssVars()` для цветов;
  - `miniApp.mountSync()` / `miniApp.ready()` для сигнала «готово»;
  - `backButton.mount()` и `backButton.show()/hide()` через `setBackButtonVisible`.

## 3. Экран «Идеи»

### 3.1. Полоса захвата

- Остаётся нативная форма верхнего уровня:
  - `#capture-strip`, `#capture-form`, `#capture-field`, `#ideas-counter`, `#status-line`;
  - логика `bindCaptureForm` и `bindCopy` не меняется (POST `/api/ideas`, статусы, событие `ideas:changed`).

- Визуально:
  - `#capture-field` — овальное поле в стиле `pocket-ui`:
    - фон как `bg-chip` референса;
    - высота не менее 16px по шрифту, чтобы не вызывать зум на iOS;
    - placeholder `Идея` как сейчас.
  - рядом pill‑кнопка «Захватить» (может быть псевдо‑кнопкой вокруг `textarea`/иконки; сабмит формы остаётся обычным).

### 3.2. Чипы полок

- Под полосой захвата — горизонтальная лента чипов:
  - первый чип: **«Все»** с числом всех идей в кармане;
  - далее по одной чипке на каждую непустую полку.
- Поведение:
  - тап по «Все» сбрасывает фильтр (`filter = null`);
  - тап по полке:
    - если сейчас не выбрана — включает фильтр по `shelf.name`;
    - если эта же полка уже выбрана — снимает фильтр.
- Вёрстка:
  - контейнер: `display: flex; gap: …; overflow-x: auto;` + класс `no-scrollbar`;
  - элементы не переносятся, строка скроллится по горизонтали, вертикальный скролл экрана не блокируется.

### 3.3. Список идей и карточка

- Структура `IdeaList` остаётся из v1:
  - `Accordion` по каждой непустой полке (`shelf-title` → список `Cell.idea-row`);
  - `selectedIdea` и `cardOpen` управляют режимом «карточка вместо списка».

- Поведение:
  - тап по строке в раскрытой полке **не копирует** текст:
    - открывает карточку (`openCard(idea)`), как в v1;
  - копирование текста происходит **только из карточки** (см. ниже).

- Визуально:
  - строки и заголовки полок можно стилизовать ближе к карточкам `IdeaCard` из референса (шрифт, плотность), без изменения семантики и доступности (role, label).

### 3.4. Карточка идеи (detail)

- Режим карточки (как сейчас в `IdeaList`):
  - `header.idea-card-header`:
    - левая кнопка назад (`IconButton.idea-card-back`);
    - заголовок (`idea-card-label`) с усечением и `title` для полного текста.
  - `idea-card-body` (clickable блок):
    - показывает `copy` с `white-space: pre-wrap`;
    - на клик:
      - проверка антидребезга `300ms` (как в v1);
      - если есть выделенный текст `window.getSelection().toString()`, копирование не запускается;
      - иначе вызывает `onCopy(copy)` → буфер обмена + статус.
  - `idea-card-delete` — кнопка удаления:
    - удаляет идею через `DELETE /api/ideas/{id}` и обновляет список/счётчик логикой v1.

- Важные отличия от референса:
  - **AvatarStack / People** из `pocket-ui` **не реализуется**:
    - нет отображения стеков аватаров;
    - нет связи id идеи с конкретным «пользователем/источником» в виде аватаров.
  - CTA‑элементы («Открыть» и т.п.) можно оставить как текст/кнопку без People‑блока.

- Интеграция с Telegram BackButton:
  - при открытой карточке:
    - полоска захвата скрывается через `setCaptureStripHidden(..., true)`;
    - `backButton.show()` через уже существующий хелпер;
  - при закрытии карточки:
    - восстанавливаем полоску (`hidden = false`);
    - `backButton.hide()`.

## 4. Экран «Sources»

### 4.1. Хедер

- Верхняя строка:
  - слева pill‑кнопка `+ Источник` → открывает форму добавления;
  - справа счётчик источников (аналог `CountBadge`): количество элементов в текущем списке.

### 4.2. Список карточек источников

- Каждый источник отображается карточкой:
  - заголовок (`title`) с кликабельной областью;
  - строка URL с трэнкатом;
  - подвал c подписью «тап открывает» и кнопкой «Удалить».

- Поведение:
  - тап по заголовку или иконке ссылки:
    - вызывает `openSourceUrl(url, openLink)` (реализация уже есть в `sourceLink.js`);
    - при недоступном `openLink` — `window.open` + ошибка при неудаче;
    - ошибка отображается через уже существующий статус `OPEN_ERROR`.
  - кнопка «Удалить»:
    - останавливает всплытие (`stopPropagation`), чтобы не открывать ссылку;
    - вызывает `DELETE /api/sources/{id}` и удаляет элемент из состояния при успехе.

### 4.3. Горизонтальная лента Sources (если используется)

- Для компактного представления (например, в верхней части экрана Sources):
  - контейнер:
    - `display: flex; gap: …; overflow-x: auto;` + класс `no-scrollbar`;
    - без переноса строк (`flex-wrap: nowrap`);
  - элементы — короткие карточки/чипы с аббревиатурой и типом (`полка`).
- UX‑правило:
  - если элементы не помещаются в строку, пользователь прокручивает по X;
  - вертикальный скролл основного контента не должен ломаться.

## 5. Форма добавления источника

- Экран по смыслу соответствует `AddSourceScreen` из референса, но упрощён:
  - поля:
    - `Название` → `title`;
    - `Ссылка` → `url`.
  - кнопки:
    - основная `Сохранить` — проверяет непустые поля и вызывает `POST /api/sources`;
    - `Отмена`/`Назад` — закрывает форму, не обращаясь к API.

### 5.1. Подсказочные чипы

- Над формой может быть ряд чипов‑подсказок (как в референсе: PH, YC, PR, AS):
  - аббревиатура (2–3 символа);
  - подпись под чипом **всегда** `полка`.
- Поведение:
  - тап по чипу:
    - заполняет `title` и `url` по предзаданных значениям;
    - **не** отправляет форму; фактическое создание источника — только по кнопке `Сохранить`.

### 5.2. Блок «Зачем»

- Заголовок `Зачем` и три иконки‑слота из референса **полностью убираются**:
  - нет текста «Зачем»;
  - нет трёх `HintSlot` с иконками;
  - нет хранения/отображения этих «объяснений» на бэкенде.

---

## 6. Аббревиатуры источников (чипы)

- Алгоритм формирования аббревиатуры по `title`:
  - разбиваем `title` по пробелам;
  - если ≥2 слов:
    - берём первые буквы двух первых слов (`Product Hunt` → `PH`, `YC Library` → `YC`);
  - если 1 слово:
    - длина ≥3: первые 2–3 символа (`Radar` → `RA`, `Яндекс` → `ЯН`);
    - длина 1–2: оставляем как есть (`YC` → `YC`).
- Применяется одинаково для латиницы и кириллицы, без обращения к бэкенду.

---

## 7. Что **не** реализуется в v2

- **People / AvatarStack / стопка аватаров**:
  - нет отображения коллекции «людей» или «источников» в карточке;
  - нет сущности People в данных, только декоративный референс.
- **Вкладка «Лента» (Inbox)**:
  - в нижнем баре — только визуальная заглушка, не активная вкладка;
  - нет роута, нет статуса `inbox` у идей, нет API для Inbox.
- **«Сводка» / статистика**:
  - иконка «Сводка» из референса в нижнем баре **не используется**;
  - графики/агрегаты по полкам и источникам в этом срезе не реализуются.
