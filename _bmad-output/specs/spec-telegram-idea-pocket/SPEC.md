# Личный карман идей

## Why

Боль: у оператора много идей, он уже бросает их в Telegram Saved Messages и иногда помечает стикером, но не всегда — без метки и пина мысль становится просто текстом среди полезных материалов и напоминалок. Нужен отдельный карман только для идей, не медленнее Saved, который можно быстро сделать.

## Capabilities

- **CAP-1**
  - **intent:** Оператор может сгрузить сырой текст идеи в хранилище только для идей — сообщением в чат бота или из поля WebApp — чтобы мысль не смешивалась с Saved Messages.
  - **success:** Сообщение боту сохраняет идею. Отправка из поля WebApp сохраняет идею, даже если перечень ещё не загрузился. Повтор любой из путей сохраняет ещё одну.

- **CAP-2**
  - **intent:** Оператор может видеть, сколько идей уже лежит в кармане, в тот момент, когда пришёл записать новую через WebApp.
  - **success:** Первый кадр WebApp показывает общее число сохранённых идей без ожидания перечня.

- **CAP-3**
  - **intent:** Оператор может просматривать сохранённые идеи в разбивке по полкам-источникам, чтобы мысль находилась как идея с происхождением, а не как строка в куче.
  - **success:** После загрузки перечня идея с полкой лежит на полке по правилам `shelves.md`; идея без полки всё равно видна в кармане.

- **CAP-4**
  - **intent:** Оператор может явно указать полку идеи, не делая этот шаг обязательным для сохранения.
  - **success:** Сохранение без полки проходит с любого канала захвата; сохранение с полкой помещает идею на эту полку, когда перечень загружен.

- **CAP-5**
  - **intent:** Оператор может выгрузить список сохранённых идей в CSV, чтобы забрать его из кармана.
  - **success:** При непустом кармане оператор получает CSV, где у каждой идеи есть текст и полка (пусто, если полка не указана).

## Constraints

- Первый кадр WebApp содержит только поле записи и общее число идей; перечень идей этот кадр не блокирует.
- Отправка из поля WebApp срабатывает всегда, независимо от того, загрузился ли перечень.
- Долгая загрузка интерфейса, куда писать в Mini App, — отказ продукта. Допустимые жесты захвата: сообщение боту или открыть Mini App и сразу писать в готовое поле.
- Полка никогда не требуется, чтобы завершить захват — ни в чате, ни в WebApp.
- В кармане лежат только идеи, не смесь материалов и напоминалок в духе Saved Messages.
- Инструмент одного оператора и короткой реализации: без LLM-пайплайна на захвате и без богатого первого кадра.
- Поверхность v1 — Telegram-бот (чат) и Mini App (WebApp).

## Non-goals

- Пуш-напоминалки писать идеи (утро / середина дня / под полночь).
- Переформулировка идеи LLM (включая proxyapi.ru и Pydantic) в момент захвата.
- Оценочные поля внутри этого продукта: ссылка на конкурента, «реальная боль», размер рынка, средний чек конкурентов, канал продвижения.
- Избранное, оценка идеи и фильтр по избранному в v1.
- Saved Messages как хранилище идей.

## Success signal

Оператор кидает мысль боту сообщением **или** открывает Mini App, видит число идей, вводит текст и отправляет, пока перечень ещё может грузиться. Идея лежит в кармане; позже перечень показывает полки. Список выгружается в CSV. Идеи больше не живут только в смешанном Saved Messages.

## Assumptions

- Один оператор, без мультипользовательского продукта.
- Счётчик на первом кадре — глобальный итог, не разбивка по полкам.
- Идею, сохранённую без полки, можно разложить по полкам позже (иначе необязательный захват противоречит важности полок).
- В чате способ указать полку не предписан; отсутствие полки в сообщении = идея без полки.
- CSV содержит как минимум текст идеи и полку; прочие колонки не специфицированы.
