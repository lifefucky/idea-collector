- (assumption) Автор не видит явных слабых мест в SPEC для telegram-idea-pocket; фордж фокусируется на поиске скрытых издержек по сравнению с текущим паттерном Saved Messages.
- (note) Автор считает трение по шагам записи пренебрежимо малым: 'приходит идея — записываю'; фордж не разжёвывает микрошаги захвата.
- (decision) Ценность кармана при извлечении: вместо долгого поиска по тегам и листания в Saved Messages оператор открывает веб-интерфейс/Mini App, видит только идеи, быстро скроллит и копирует нужные описания.
- (assumption) Режим извлечения по умолчанию — отбор и перенос идей в другие системы (backlog, документы, задачи), а не просто вдохновение: пользователь ожидает быстро просматривать и забирать конкретные идеи.
- (decision) В v1 допускается минимальный маркер на идее (например, "обработано"), фиксирующий, что идею уже забрали/разобрали при просмотре перечня или выгрузке.
- (decision) Маркер обработки в v1 один общий (булевый): идея либо ещё не тронута, либо уже "обработана/забрана" автором, без детализации каналов вывода.
- (assumption) Чекбокс/маркер 'обработано' не критичен для v1: продукт остаётся приемлемым без него; можно вынести в последующие версии.
- (lock) Карман остаётся продуктом только для идей: ссылки, материалы и напоминалки продолжают жить в Saved Messages или других местах по дисциплине автора.
