# Личный карман идей — Experience Spine

Визуал — `DESIGN.md`. Спины побеждают любой мок, импорт и последующую вёрстку.

## Foundation

Две поверхности Telegram, без отдельного сайта и без ЛК: **чат бота** и **Mini App**. UI-системы нет — Mini App наследует Telegram Mini Apps и токены `DESIGN.md`. Один оператор; идентичность = аккаунт Telegram; экрана входа нет.

Основной форм-фактор — телефон в Telegram. Mini App в Telegram Desktop — та же одноколоночная вёрстка, не отдельный desktop-layout.

Дефолтный сценарий — извлечение: открыл список, забрал конкретное, ушёл. Захват без микроспека шагов. В v1 у идеи нет статуса «обработано».

## Information Architecture

| Surface | Reached from | Purpose |
|---|---|---|
| Mini App | WebApp из бота / Telegram | захват, счётчик, идеи по полкам (CAP-3) |
| Чат бота | диалог с ботом | захват сообщением (CAP-4); вход в Mini App |

Mini App — один экран: без таббара, настроек, профиля и модалок.

Состав сверху вниз: `capture-field` + `ideas-counter` → список `shelf-group` → в раскрытой полке `idea-row`.

Полка группирует список (CAP-3). Имена — из `shelves.md`: агрегатор = своё имя; чужой продукт → `чужие приложения`; своя мысль → `идея собственная`. Полку ставит LLM в ответе модели (override: в `shelves.md` полку указывает оператор). На захвате полка необязательна (CAP-4), одинаково в чате бота и в `capture-field`. Идея без полки остаётся в перечне и показывается в `идея собственная`.

Порядок полок UX не задаёт: стабильный порядок с данных, без алфавитного UI и «избранного».

Мокапов нет. Mini App и чат бота — spine-only.

## Voice and Tone

Микрокопи. Бренд-голоса нет (`DESIGN.md`). Тон — утилита для себя.

| Do | Don't |
|---|---|
| Счётчик как число | «У тебя уже 12 идей! 🚀» |
| Имена полок как в `shelves.md` | Переименовывать полки для UI |
| Плейсхолдер `capture-field`: «Идея» | Онбординг и подсказки «как пользоваться» |
| После копирования: «Скопировано» | Тост-поздравление, конфетти |
| Ошибка одной строкой, что сломалось | Коды ошибок, «обратитесь в поддержку» |

## Component Patterns

Поведение. Визуал — секция Components в `DESIGN.md` и токены `{colors.*}`, `{typography.*}`, `{rounded.*}`, `{spacing.*}`.

| Component | Use | Behavioral rules |
|---|---|---|
| capture-field | Mini App, верх | Тот же захват, что сообщение боту (CAP-4). Отправка кладёт идею в список, полку берёт из ответа LLM, `ideas-counter` +1. Полка в поле необязательна. Пока ответа нет — поле не принимает вторую отправку. Успех очищает поле и раскрывает целевую полку, даже если она была свёрнута. |
| ideas-counter | Mini App, верх, рядом с полем | Число всех сохранённых идей в кармане, не на открытой полке. Не кликабелен. |
| shelf-group | Mini App, список | Тап по хедеру раскрывает или сворачивает. Старт: все полки свёрнуты. Рендер только полок с хотя бы одной идеей. |
| idea-row | внутри раскрытой `shelf-group` | Тап копирует текст идеи в буфер и оставляет оператора на том же экране. Детали нет. В v1 нет маркера «обработано». |

## State Patterns

| State | Surface | Treatment |
|---|---|---|
| Холодная загрузка | Mini App | Скелет верхней полосы и 2–3 хедера полок, затем данные. |
| Пустой карман | Mini App | `capture-field` и `ideas-counter` = `0`. Списка полок нет. Без иллюстрации и без CTA кроме поля. |
| Пустая полка | Mini App | Не рендерится. |
| Идея без полки от LLM | Mini App | Строка в `идея собственная`. Группы «без полки» нет. |
| Отправка из поля | Mini App | Поле ждёт ответ. Успех: пустое поле, строка в нужной полке, полка раскрыта, счётчик +1. |
| Ошибка захвата | Mini App / чат бота | Текст остаётся в поле или в черновике чата. Короткая ошибка `{colors.destructive}`. Повтор — снова отправить. Счётчик не увеличивается. |
| Ошибка копирования | Mini App | Строка на месте. Короткая ошибка `{colors.destructive}`. Повторный тап. |
| Офлайн | Mini App | Показать уже загруженный список, если он есть. Захват не считается успешным, пока карман не принял идею. |
| Фокус | capture-field | Системная клавиатура Telegram. Каретка в поле, обводка `{colors.accent}`. |

## Interaction Primitives

- Тап по хедеру `shelf-group` — раскрыть или свернуть.
- Тап по `idea-row` — скопировать текст.
- Отправка из `capture-field` — захват.
- В чате бота — нативная отправка сообщения Telegram.
- Список полок и идей скроллится быстро: длинный карман — это скролл, не пагинация и не поиск в v1.
- Long-press на тексте идеи не перехватывается: системное выделение Telegram/OS остаётся; основной путь — короткий тап.
- **Запрещено в v1:** ЛК, логин, таббар, свайп-удаление, цветные фильтры полок, статус «обработано», онбординг.

## Accessibility Floor

Визуальный контраст — `DESIGN.md`. Стейки: личный бот, не публичный consumer.

- Тап-цели хедера полки и `idea-row` ≥ 44pt.
- Счётчик не единственный носитель смысла: рядом поле и список.
- Имя полки — доступное имя группы; состояние свёрнуто/раскрыто объявляется.
- В Telegram Desktop порядок фокуса: `capture-field` → хедеры полок → строки идей, по чтению сверху вниз.
- Reduce Motion: аккордеон без анимации, раскрытие мгновенное.

## Responsive & Platform

| Поверхность | Поведение |
|---|---|
| Telegram iOS/Android Mini App | Один столбец: захват сверху (`{spacing.4}` по горизонтали), список ниже. |
| Telegram Desktop Mini App | Тот же столбец, не двухпанельный layout. |
| Чат бота | Нативный чат. Основной UI извлечения — Mini App, не история сообщений. |

## Inspiration & Anti-patterns

- **Отвергнуто — Saved Messages как UI:** каша из материалов и напоминалок. Здесь только идеи.
- **Отвергнуто — ЛК / аккаунт / профиль:** карман личный, пользователь один.
- **Отвергнуто — режим вдохновения:** дефолт — отбор и перенос наружу.
- **Отвергнуто — отдельная группа «без полки»:** такие идеи живут в `идея собственная`.
- **Не копировать витрины агрегаторов:** полка — имя источника, не карточка Product Hunt.

## Key Flows

Протагонист — **Оператор**, единственный пользователь личного бота.

### Flow 1 — Захват в Mini App (Оператор, идея только что пришла)

1. Оператор открывает Mini App.
2. Видит `capture-field` и `ideas-counter`.
3. Пишет идею в поле, отправляет. Полку не указывает (CAP-4).
4. LLM возвращает полку в ответе.
5. **Climax:** идея видна в нужной `shelf-group` (или в `идея собственная`), счётчик +1, поле пустое — Telegram можно закрыть.

Failure: ответа нет или ошибка — текст остаётся в поле, счётчик не врёт, повторная отправка.

### Flow 2 — Захват в чате бота (Оператор, быстрее написать в диалог)

1. Оператор открывает чат бота.
2. Шлёт текст идеи сообщением (CAP-4).
3. Бот/модель отвечает; полка из ответа LLM.
4. **Climax:** идея в кармане. Список смотрит в Mini App, не в истории чата.

Failure: идея не считается сохранённой, пока карман её не принял.

### Flow 3 — Забрать конкретное (Оператор, открыл карман чтобы вытащить мысль в другую систему)

1. Оператор открывает Mini App, чтобы забрать одно конкретное.
2. Быстро скроллит список полок (CAP-3).
3. Тапает нужную `shelf-group`, она раскрывается.
4. Тапает `idea-row`.
5. **Climax:** текст в буфере, на экране «Скопировано» — можно уйти в backlog / документ / задачу и вставить.

Failure: копирование не удалось — строка на месте, ошибка, повторный тап; Mini App никуда не навигирует.
